这篇文章解决的是三类人的问题：

- 想做外贸 B2B 独立站，但不会写代码。
- 想用 AI 建站，但总是停留在“做个首页”的阶段。

## 你在用 AI 之前，先准备这 10 样东西

别一上来就说“给我做个网站”。真正高效的方式，是先把 AI 需要的业务上下文喂进去。

如果你打算做纯静态网站，又想让联系表单可以直接收询盘，那这个阶段就先去 [Web3Forms](https://web3forms.com/) 注册免费表单服务，验证邮箱后拿到 `access_key`。这个 key 不要等网站做完了再补，而是和 Logo、联系方式一起打包发给 AI，这样它第一次生成联系页和询盘区块时，就能直接把 B2B 表单接好。

你给 AI 的资料越清晰，它越像一个执行助理；你给它的信息越模糊，它越像一个随机网页生成器。

## 为什么我不建议你一上来就发一句“帮我做个网站”

因为这句话只会触发 AI 的“页面生成模式”，而不会触发它的“工程协作模式”。

对外贸 B2B 站来说，真正应该先搭的是这些底层模块：

- 全局布局
- 导航和页脚
- 文章页模板
- 分类页模板
- 联系页和询盘表单
- SEO Head 组件
- JSON-LD 结构化数据
- 干净 URL 规则
- 内链和分类承接逻辑

所以，正确顺序从来不是“先首页，后面再说”，而是：

1. 先定规则
2. 再定页面体系
3. 再让 AI 按模块写代码
4. 最后才是不断扩内容、扩页面、扩流量入口

## 第 0 步：先让 AI 进入“建站向导模式”

这一步非常重要。你不先定角色，AI 就会一会儿像程序员，一会儿像百科，一会儿像写手，输出风格很散。

```text
从现在开始，你是我的外贸独立站专属执行向导，全程用大白话指导我完成「Astro 纯静态外贸 B2B 站搭建 + Cloudflare 免费部署」全流程。

所有代码编写、命令行操作、配置文件修改全部由你自动完成，不需要我手动敲代码。
遇到任何报错，自动排查原因，用普通人能听懂的话告诉我为什么出错、现在该怎么处理。
每一步只让我做 1 件简单的事，做完再进入下一步。

这个网站必须满足以下要求：
1. 面向外贸 B2B，适合 Google SEO 和 AI 时代的 GEO
2. 使用 Astro 纯静态架构
3. 页面结构清晰，URL 用纯小写英文加短横线
4. 页面需要可长期维护，不做一次性首页
5. 以移动端适配、加载速度和可抓取性为基础

现在先从环境检查开始。
```

## 第 1 步：先让 AI 做能力自检

不要急着生成代码，先让 AI 把自己的执行边界说清楚。

```text
现在先不要生成网站代码。请先做一次能力自检，并用大白话告诉我：

1. 你能自动帮我完成哪些事情
2. 哪些步骤需要我手动点击或授权
3. 你建议我本次先走“本地预览 + 练习部署”还是“直接做正式项目”
4. 这次项目里，哪些技术点最容易让建站小白卡住

最后给我一个你推荐的整体执行顺序。
```

这一段的目的，是让 AI 从“执行器”切换成“陪跑型工程助理”。

## 第 2 步：环境准备提示词

这一步的目标不是折腾命令行，而是把 Astro、Node、Wrangler、Cloudflare 登录权限这些地基一次性处理干净。

```text
现在帮我检查并配置建站所需环境：

1. 检查我电脑上的 Node.js 是否满足 Astro 当前官方要求；如果不满足，请指导我升级到合适的稳定版本。
2. 在当前项目里按 Cloudflare 官方推荐方式安装 Wrangler，并告诉我以后应该如何调用它。
3. 检查 npm 是否正常可用。
4. 一步一步引导我完成 Cloudflare 登录授权。
5. 全部完成后，用一句人话告诉我：环境现在是否已经可以开始建站。
```

这里我要补一句：**你让 AI 检查官方要求，比你自己死记版本号更稳。** 因为技术栈会变，文档会更新，但“先让 Agent 核对官方要求”这个动作不会过时。

## 第 3 步：生成 Astro 项目骨架

这一步不要只说“做个首页”，要让 AI 按完整的 B2B 站点结构起工程。

这里建议你在发这一步之前，先把品牌 Logo 设计好，并且把 Logo 图片先保存到你电脑里。  
原因很简单：导航栏、页脚、网站 favicon、分享缩略图、品牌感，最好从一开始就统一。  
你只要把 **Logo 的本机图片路径** 一起发给 AI，它就能在建站时顺手把图片拷进项目资源目录，并统一应用到网站里。

```text
现在在当前目录下，帮我创建一套完整的 Astro 纯静态外贸 B2B 独立站项目。

请按下面信息生成：
- 项目英文名：[PROJECT_NAME]
- 品牌名：[BRAND_NAME]
- 行业品类：[INDUSTRY]
- 目标市场：[TARGET_MARKETS]
- 主营产品：[MAIN_PRODUCTS]
- Logo 图片本机路径：[LOGO_FILE_PATH]
- Web3Forms Access Key：[WEB3FORMS_ACCESS_KEY]
- 联系邮箱：[CONTACT_EMAIL]
- WhatsApp：[WHATSAPP]

具体要求：
1. 页面包含：首页、关于我们页、服务/产品列表页、产品详情模板、FAQ页、博客列表页、博客详情页模板、联系我们页，并且联系我们页要带可用的 B2B 询盘表单。
2. 导航、页脚、SEO Head、面包屑、询盘表单都要封装成可复用组件。
3. URL 必须使用纯小写英文加短横线，不要中文，不要子目录乱套。
4. 全站优先纯静态输出，强调速度、可抓取性、可维护性。
5. 每个页面都预留 Title、Description、Open Graph、JSON-LD 的生成能力。
6. 建站时请使用我提供的 Logo 图片，把它放到项目合适的图片目录，并应用到导航栏、页脚、网站 favicon 和基础品牌展示区域。
7. 请使用我提供的 Web3Forms Access Key，把联系表单直接接好，并把表单放到合适的位置，至少包含 name、email、message 等基础询盘字段。
8. 风格走简洁专业的外贸 B2B 路线，不做花哨营销页。

生成完成后，请先简洁说明项目结构，再进入下一步。
```

## 第 4 步：要求 AI 把 SEO 和 GEO 底层规则固化进去

这是很多人最容易跳过的一步。结果就是站做出来了，但 URL 乱、H 标签乱、内链乱、结构化数据没上，后面又得返工。

```text
现在不要急着加内容，请先把全站的 SEO 和 GEO 基础规则固化：

1. 所有页面必须具备清晰的 title、meta description 和 canonical 逻辑。
2. 使用语义化 HTML：header、nav、main、article、aside、footer。
3. 为站点补充适合的 JSON-LD，包括 Organization、WebSite、BlogPosting、FAQPage 等可复用能力。
4. 博客、分类页、详情页之间必须形成结构化内链，避免孤岛页面。
5. 重要导航、分类、页脚链接必须是真实可抓取的 HTML 链接。
6. 页面正文不要依赖脆弱的 JavaScript 才能看到核心内容。
7. 整体规则要兼顾 Google SEO 和 AI 时代的机器可读性。

完成后，请告诉我：哪些 SEO 底层规则已经固化，后续发文章时会自动继承。
```

这一步做完，你后面每加一个页面、每发一篇文章，效率都会高很多。

## 第 5 步：先把页面模板体系、组件体系和 Skill 规则封装好

做到这一步，千万不要急着马上本地预览。因为很多 AI 建站项目真正的坑，不是“跑不起来”，而是“每加一个页面就像新做一个网站”。  
对外贸 B2B 独立站来说，正确顺序应该更像 WordPress 建站的模板逻辑：**先想清楚网站有哪些页面类型，再把这些页面类型的模板、共用组件和 SEO 规则统一封装。**

你可以把它理解成程序员常说的 OOP 模块化思维，也就是一句很朴素的话：**一次封装，全局调用。**  
后面你只改一个模块文件，整站相关页面就一起更新，而不是每个页面都去手改一遍。

这一层至少要想清楚三件事：

- **业务页面模板有哪些**：首页、关于我们、FAQ、联系我们、博客分类页、博客详情页、解决方案页、产品列表页、产品详情页、行业案例页等。
- **博客体系怎么防孤岛**：博客详情页右侧边栏必须用真实 HTML 锚文本链接到博客分类页和推荐文章；博客列表页负责挂载详情页，给蜘蛛一条稳定的抓取路径。
- **通用组件怎么复用**：固定导航栏、页脚、版权信息、询盘组件、SEO Head、面包屑、CTA 区块这些都应该独立封装。

```text
现在不要急着进入本地构建。请先按 WordPress 建站的模板思路，为这个 Astro 外贸 B2B 项目设计完整的页面类型体系、通用组件体系，以及后续可重复调用的 Skill 规则。

请按以下要求执行：

1. 先梳理这个网站至少应该有哪些页面类型：首页、关于我们、FAQ、联系页、博客分类页、博客详情页、解决方案页、产品列表页、产品详情页、行业案例页等。
2. 参考 WordPress 不同页面模板的设计思路，为每一类页面定义统一的排版结构、内容区块顺序、SEO 字段和内链规则。
3. 博客详情页右侧边栏必须使用真实可抓取的 HTML 锚文本，先展示博客分类列表，再展示推荐文章列表，让博客详情页把蜘蛛引回博客列表页，避免孤岛页面。
4. 博客列表页必须负责挂载博客详情页，并为不同分类生成对应的实体 URL 列表页。
5. 除了业务页面模板，再封装全站通用组件：固定导航栏、页脚、版权信息、询盘组件、SEO Head、面包屑、CTA 区块等。
6. 这套组件和页面模板要按照面向对象 OOP 的模块化思路组织，做到“一次封装、全局调用”；后续如果修改单个模块文件，全站相关页面可以自动同步更新。
7. 请把页面模板规则和组件规则分别整理成可复用的 Skill 文档，或者固定提示词模板，供后续重复调用，尽量减少重复解释和 Token 消耗。
8. 适配 AI 执行逻辑：基于 Astro 面向对象模块化架构，加载对应页面 Skill 模板，统一同类页面结构、UI 样式、SEO 规范与内容布局，新页面直接复用封装模块，不要每次重新定义规则。

完成后，请告诉我：
1. 当前项目已经具备哪些页面模板
2. 当前项目已经具备哪些通用组件
3. 哪些 Skill 文件已经可以固定复用
4. 哪些模板或组件还需要补
```

这一段本质上是在告诉 AI：**你现在不是随手拼页面，而是在搭一套可长期维护的站点工程系统。**  
这一步做对了，后面扩产品、扩博客、扩案例页，整站风格、结构和 SEO 逻辑才不会越做越乱。

## 第 6 步：本地构建与预览

AI 建站最怕一种错觉：代码文件很多，看起来很忙，但项目根本跑不起来。所以这一步必须让 AI 真构建、真预览、真修错。

```text
现在帮我完成本地构建检查：

1. 自动安装项目依赖。
2. 运行构建命令，检查是否有报错。
3. 如果有报错，请先修复再继续。
4. 构建成功后，启动本地预览服务。
5. 告诉我本地访问地址，并提醒我重点检查哪些页面。
6. 如果你发现页面存在排版、响应式、语义结构或 SEO 方面的问题，请主动继续修。
```

你在这一阶段要重点看 4 个点：

- 页面有没有明显错位
- 导航、页脚、文章页模板是否统一
- 手机端是否能正常看
- 页面内容和链接是不是一眼就能看明白

## 第 7 步：先做一次 Cloudflare Pages 练习部署

如果你只是想先熟悉部署流程，可以走一遍本地构建 + Wrangler 上传。这个方式很适合练手。

```text
现在帮我把构建好的静态站点部署到 Cloudflare Pages 做练习预演：

1. 使用 Cloudflare 官方支持的方式部署当前构建输出目录。
2. 如果需要创建 Pages 项目，请用清晰步骤引导我授权和确认。
3. 部署成功后，把线上预览链接发给我。
4. 同时告诉我：这个项目是 Direct Upload 还是 Git 集成，以及这两者后续维护上的区别。
```

这里有一个非常实操的提醒：**Cloudflare 官方文档写得很清楚，Direct Upload 项目后面不能直接切换成 Git integration。** 所以如果你只是练手，这个方式很好；如果你准备做长期正式站，建议单独创建一个 Git 接入的正式项目。

## 第 8 步：正式上线版提示词

当你本地看顺眼了，结构也稳定了，再进入正式上线流程。

```text
现在请按正式上线项目的标准，指导我完成以下事情：

1. 把当前项目整理为适合长期维护的正式版本。
2. 在 Cloudflare Pages 里创建正式项目，并告诉我应该选择哪种部署方式更适合长期维护。
3. 绑定我的正式域名：[DOMAIN]
4. 告诉我 DNS、SSL、生产域名生效后分别该如何检查。
5. 上线后，再给我一份 SEO 上线检查清单，确保站点具备被 Google 正常抓取和收录的基础条件。
```

## 第 9 步：正式上线后的 SEO 检查

这一段我建议你一定不要省。很多人把网站推上 Cloudflare 之后，就觉得大功告成了。其实真正的 SEO 工作，往往是上线后才开始。

尤其是用 AI Agent 辅助建站时，最容易出现的问题不是“页面做不出来”，而是：

- 某些页面能打开，但没有被内链接住
- Title、Description、H1 有重复或缺失
- 301、302、404 处理不干净
- canonical 写错
- noindex、robots、重定向规则互相打架
- 图片 alt、结构化数据、分页、分类页细节漏掉

这些问题，靠肉眼一个个翻网页，效率太低。更稳的方式，是在正式上线后，马上用专业爬虫工具把整站自动扫一遍。

### 为什么我建议一定要用尖叫的青蛙

**Screaming Frog SEO Spider** 这个工具，官方能力本来就是拿来做技术 SEO 巡检的。它最适合你在网站上线后，快速排查这些问题：

- 死链、404、5xx 报错
- 301/302 跳转链和跳转循环
- Title、Meta Description 过长、过短、缺失、重复
- H1、H2、canonical、meta robots 异常
- 重复内容、低内容页、图片 alt 缺失
- hreflang、结构化数据、站点地图、内链深度等问题

如果你的网站规模不大，官方免费版先拿来跑一遍就已经很有用了；如果页面量更大，再考虑上付费版。

### 这一段不是写提示词，而是你本人要在电脑上做

这一步不要再发给 AI 了，而是你自己在本地电脑打开 **Screaming Frog SEO Spider**，直接把刚上线的网站当成谷歌蜘蛛先爬一遍。目的很明确：**不要让网站带着明显错误上线后长期裸奔。**

你就按这个顺序做：

1. 打开 Screaming Frog，把你的正式域名填进去，先完整爬一次站。
2. 第一轮先重点看 5 类问题：`Response Codes`、`Page Titles`、`Meta Description`、`H1`、`Directives`。
3. 接着看 `Canonicals`、`Images`、`Inlinks`、`Sitemaps`，把 canonical 错误、图片 alt 缺失、孤岛页面风险、站点地图遗漏一起找出来。
4. 发现问题不要先记着“以后再说”，而是立刻回到项目里修改。
5. 修改完以后，不是结束，而是再爬一轮，再检查一轮。
6. 一直循环到 404、错误跳转、重复标题、重复描述、H1 缺失、canonical 错误、noindex 误伤、孤岛页面这些核心问题都处理干净。

你要记住，这一步本质上是在**网站刚上线时就先模拟一次谷歌蜘蛛的真实抓取**。有问题立马改，改了再排查，这样才能保证你的 SEO 站不是“先上线再慢慢烂”，而是从第一天开始就把细节尽量做完整。

如果你是小白，第一次巡检时，优先级可以这样排：

- 先修 404、5xx、错误跳转
- 再修 Title、Description、H1 重复或缺失
- 再修 canonical、noindex、robots 这类会直接影响收录的项目
- 最后再处理图片 alt、分页、结构化数据、内链深度这些细节项

### 一个很实在的补充

尖叫的青蛙在国内 SEO 圈子里并不算陌生。除了看官方定价页，国内也常有人在淘宝找购买渠道，价格通常会便宜一些。这个可以作为你的成本优化思路，但购买前一定要自己核验授权方式、稳定性和售后，不要只看便宜。

## 报错时，不要慌，直接把这段丢给 AI

这是我很推荐保留的一段“故障恢复提示词”。很多小白不是不会建站，而是报错后不知道下一句话怎么问。

```text
我现在遇到了报错。请你按下面顺序处理：

1. 先用一句大白话告诉我：这个错误大概率是什么意思。
2. 不要同时给我 5 个方案，先给我当前最可能有效的 1 个方案。
3. 你直接执行修复，或者明确告诉我只需要点哪里。
4. 修复后请重新运行刚才失败的命令。
5. 最后告诉我：问题是否已经彻底解决，下一步该做什么。
```

这段话会让 AI 从“知识型回答”切回“解决问题模式”。

## 你和 AI 沟通时，要盯住哪 6 个关键点

很多人以为提示词越长越强。其实不是。真正重要的，是你每一轮都要盯住几个不会变的关键点。

    <strong>先定结构，再做页面</strong>
  </div>
  <div>
    <span>规则 02</span>
    <strong>先定 URL，再批量扩内容</strong>
  </div>
  <div>
    <span>规则 03</span>
    <strong>先固化 SEO，再谈 GEO</strong>

- 网站是不是模块化的，而不是零散页面拼起来的
- URL 规则是不是统一的
- 页面是不是可抓取、可索引、可读的
- 重要页面之间有没有内链承接
- 内容是不是以真实业务和真实买家问题为中心
- 后面如果批量发文章，模板是不是还能持续复用

## AI 时代的 SEO/GEO，真正该重视的不是花招

如果你问我：符合 Google SEO 和 AI GEO 标准的网站，最核心的共同点是什么？

我的答案是：**它首先是一个正常的网站。**

Google 最新 AI 搜索优化指南已经把方向说得很清楚了：

- 生成式搜索不是替代 SEO，而是建立在 SEO 之上
- 有价值、非同质化、有人类经验的内容更重要
- 可抓取、可索引、结构清晰的页面依然是底盘
- 不需要为了 AI 去发明一堆奇怪的“特殊文件”和“神秘格式”

所以你用 Codex、Claude Code、Hermes Agent 搭站时，真正该让它帮你固化的是这些：

- 清晰的语义结构
- 干净的站点架构
- 高质量的内容模板
- 稳定的部署流程
- 长期可维护的组件体系

而不是天天研究“AI 喜欢不喜欢某个玄学标签”。
