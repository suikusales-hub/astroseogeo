这篇我们更进一步，直接讲一个成熟运营或技术 SEO 应该怎么拿它做一次全盘大体检。

## 先讲一个关键认知：Screaming Frog 不是问题列表生成器

很多人第一次跑青蛙，会很兴奋，因为它一下子给出几百上千条问题。  
但真正有经验的人不会被数量带偏。

因为技术 SEO 审计最怕的，不是问题太少，而是：

- 问题很多
- 但没排序
- 没跟业务页面挂钩
- 修了一堆不重要的小毛病，却放过了真正影响抓取、索引和转化的主问题

所以青蛙最值钱的地方，不是“抓得多”，而是你能不能把抓出来的信息排出优先级。

## 一次全盘体检，应该先看哪 7 层

### 第一层：状态码与可访问性

这是所有审计的地基。

先看：

- 200 页有多少
- 3xx 页有多少
- 4xx 页有多少
- 5xx 是否存在

如果一个网站大量内部链接指向 3xx、4xx 页面，后面你谈内容、内链、结构化数据，都会显得很虚。

### 第二层：标题、描述、H1 基础标签

这一层不是为了“机械补齐标签”，而是快速判断站点模板和内容质量是否失控。

重点看：

- Title 缺失
- Title 重复
- Meta Description 缺失
- H1 缺失
- 多 H1

如果大批页面在这些地方混乱，通常意味着模板问题，不是单页问题。

### 第三层：Canonical 与索引信号

这一层尤其关键。

你要看：

- 页面自指 canonical 是否正常
- 是否大量 canonical 指向不合理目标
- noindex 页面和 canonical 信号是否冲突
- 参数页、筛选页、标签页是否在争抢主版本

很多站索引不稳定，真正的问题都在这一层。

### 第四层：内链结构与点击深度

一个页面能不能被稳定抓取、理解和获得权重支持，很大程度上取决于它在整站结构里处于什么位置。

我会重点看：

- Click depth
- Inlinks
- 是否存在深埋页
- 是否存在重要页面内链支持过弱

### 第五层：图片与前端资源

很多独立站页面视觉做得很满，但图片、资源管理很乱。  
这会影响：

- 页面速度
- 移动端体验
- 抓取效率
- 图片 SEO

尤其在电商站里，图片体积和 alt 缺失是常见顽疾。

### 第六层：渲染与 JS 可见内容

现代站点前端越来越重，如果你的网站依赖 JS 输出主体内容，必须确认：

- 渲染后内容是否完整
- 关键文本是否真的出现在 DOM 里
- canonical、meta robots 等信号是否在渲染后稳定

### 第七层：结构化数据与模板一致性

这一步适合抽查：

- 文章页 Schema 是否完整
- 产品页结构化数据是否一致
- 是否存在模板漏加或错配

## 为什么很多人跑完青蛙，还是不知道该改什么

因为他们没有把青蛙输出和页面价值对应起来。

比如同样是 404：

- 一个是被导航强推的核心分类页链接出错
- 一个是某篇冷门旧文里提到的外部资源失效

优先级完全不是一个级别。

所以青蛙的结果一定要分层：

- 钱页优先
- 高曝光页优先
- 入口页优先
- 模板级问题优先

而不是看到什么修什么。

## 我最常用的一套审计顺序

### 第一步：设定 crawl 边界

你要先知道这次体检是查什么：

- 全站
- 某个目录
- 某类模板
- 某个国家版本

范围不清，输出就会变得很噪。

### 第二步：先跑 HTML 基础抓取

先拿到：

- URL 总量
- 状态码分布
- Title / H1 / Meta 概况
- Canonical 概况

这一步是看站的骨架。

### 第三步：再看链接结构

重点筛：

- 重要页面的内链数量
- 过深页面
- broken internal links
- redirecting internal links

### 第四步：按模板导出问题

比如：

- 产品页标题重复
- 博客页 H1 缺失
- 分类页 canonical 错指

这时你已经能从“单条错误”上升到“模板错误”了。

### 第五步：结合 GSC 做交叉验证

青蛙看到的是网站结构，GSC 看到的是 Google 实际结果。  
两者结合，优先级会非常清楚。

例如：

- 青蛙发现某类页面 click depth 太深
- GSC 刚好显示这类页面“发现但未索引”很多

那就不是猜，是证据链。

## 外贸 B2B 与跨境 B2C，用青蛙审计时重点不同

### B2B 站更应该重点看

- 产品参数页和解决方案页是否被深埋
- 询盘页、联系页内链是否足够
- 多语言版本是否存在重复与错 canonical
- 博客页是否真的在给产品页输送内链

### B2C 站更应该重点看

- 集合页与产品页链接结构
- 过滤页、参数页是否造成索引噪音
- 图片体积与 alt 完整性
- 促销页和季节页是否有大量失效链

## 哪些问题最值得你第一时间处理

如果让我给一轮青蛙审计结果排序，我通常优先这几类：

1. 重要页面 4xx / 5xx
2. 重要页面 canonical 错误
3. 重要页面被 noindex 或 robots 误伤
4. 重要页面点击深度过深、内链支持不足
5. 模板级 Title / H1 / 描述混乱
6. 大量内部链接指向重定向 URL
7. 图片体积过大导致关键页面体验差

这几类问题，往往比“少数页面 meta description 为空”更值得先动。

## 为什么我说青蛙最适合做“结构复盘”

因为你会发现，很多网站的问题不是新问题，而是长期积累问题：

- 建站时图方便留下的旧模板
- 迁移时没清理干净的旧 URL
- 编辑长期发文却不管内链
- 产品上下架后遗留的大量无效页面

青蛙会把这些“平时看不到、规模上一看很吓人”的东西全部摊开。

## 最后一句话

青蛙不是拿来“证明你很懂技术”的，而是拿来帮你决定：  
这个月网站最该先修什么。

当你能把它从“错误列表生成器”用成“结构优先级工具”，这只青蛙才算真的开始替你干活。
